// 오후 ① agent 노드
return { messages: [reply], steps: 1 };
[NODE  ] ▶ agent · 받은 State: messages 2개, steps 0
[NODE  ] ▶ agent · 받은 State: messages 4개, steps 1
[NODE  ] ▶ agent · 받은 State: messages 6개, steps 2
  • agent 는 매번 메시지 하나와 숫자 1 만 돌려줬다
  • 그런데 State 의 messages 는 2 → 4 → 6 으로 늘고, steps 는 0 → 1 → 2 로 올랐다
  • reducer 를 빼면 messages 가 계속 1개였다 (오후 ① 실습 07)
  • 이 세션의 질문: 노드가 돌려준 값은 State 에 어떻게 들어가나?

노드가 돌려준 값 → reducer → State

flowchart LR
  N["노드: 바꾼 칸만 돌려준다"] --> R["reducer: 칸마다 정해 둔 규칙으로 합친다"]
  P["지금 State"] --> R
  R --> S["새 State"]
  S --> N2["다음 노드"]
  • 노드는 State 를 직접 고치지 않는다. "이 칸을 이렇게 바꾸고 싶다" 고 돌려줄 뿐
  • 합치는 건 LangGraph 가 한다. 칸마다 적어 둔 reducer 로
  • 그래서 노드는 자기 칸만 신경 쓰면 된다. 다른 노드가 무엇을 썼는지 몰라도 된다
  • 노드 두 개가 같은 칸에 동시에 써도 규칙만 있으면 안전하다 (뒤에서 시연)

// agent 노드: State 에는 전부 남기고, 모델에게는 최근 것만
const res = await chat(keepRecent(state.messages, 4), TOOLS);

function keepRecent(messages, n) {
  const head = messages.slice(0, 2);       // system + 질문
  let tail = messages.slice(2).slice(-n);
  while (tail[0]?.role === "tool") tail = tail.slice(1);
  return [...head, ...tail];               // 도구 결과만 덩그러니 남지 않게
}

오후 ② 정리

  • 노드는 State 를 직접 고치지 않는다. 바꾸고 싶은 칸만 돌려준다
  • 합치는 규칙은 칸마다 reducer 로 정한다: 덮어쓰기 · 이어 붙이기 · 더하기 · 직접 짠 규칙
  • 같은 단계에서 두 노드가 같은 칸에 쓰려면 reducer 가 있어야 한다
  • State 에 없는 칸은 조용히 버려진다
  • State 는 기록 전부, 모델에게 무엇을 보낼지는 노드가 고른다
  • stream 으로 돌리면 노드가 돌려준 값과 합친 State 를 하나씩 볼 수 있다
